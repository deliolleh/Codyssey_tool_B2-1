
## 의도
- 단순한 프로그램 작성이 아닌, 유지보수 가능한 설계로 완성
	- 기능이 많은 것이 아닌, 예외 상황에서도 데이터가 안전한 것
- Python 기반 가계부 콘솔 프로그램
	- 수입/지출 내역 저장
	- 수정/삭제
	- 검색
	- 월별 요약
	- 카테고리 관리
	- 예산 초과 경고
- 터미널에서 명령어를 이용해 작업
	- 추가(add), 조회(list), 검색(search), 요약과 리포트 출력(summary), 내보내기(export), 가져오기(import)
	- 데이터는 JSONL 또는 CSV 파일로 영구 저장
- 저장 파일을 제너레이터로 스트리밍 처리
	- 저장 파일을 한 번에 모두 읽지 않게 하기
- 데코레이터로 공통 기능 분리
	- 예외 처리
	- 실행 로그
	- 실행 시간 측정
- 타입 힌트 적용
	- 함수와 데이터 구조의 계약 명확히 구분
	- 모듈 분리를 통한 유지보수 구조 설계

## 최종 결과물
1. 거래 추가 - add
	1. 입력/요청: 대화형 입력(날짜, 타입, 카테고리, 금액, 메모/태그)
	2. 출력/화면: 저장 성공 메시지, 생성된 거래 `id`
2. 거래 목록 - list
	1. 입력/요청: `-limit` 등 옵션
	2. 출력/화면: 최신순 거래 리스트(스트리밍 처리)
3. 거래 검색 - search
	1. 입력/요청: `-from/--to`, `-category`, `-type`, `-q`, `-tag`
	2. 출력/화면: 조건에 맞는 거래 리스트(최신순)
4. 월별 요약 - summary
	1. 입력/요청: `-month YYYY-MM`, `-top N`
	2. 출력/화면: 총수입/총지출/잔액, 카테고리별 지출 TOP N
5. 예산 설정/조회 - budget
	1. 입력/요청: `budget set --month YYYY-MM --amount 금액`
	2. 출력/화면: 저장 성공 메시지 + summary에서 예산 사용률/초과 경고
6. 카테고리 관리 - category
	1. 입력/요청: `category add/list/remove`
	2. 출력/화면: 카테고리 목록/추가/삭제 결과(사용 중 카테고리 처리 포함)
7. 거래 수정 - update
	1. 입력/요청: `-id` 기반(옵션 방식 또는 대화형 중 1개로 **고정**)
	2. 출력/화면: 수정 성공/실패 메시지(없는 id 처리 포함)
8. 거래 삭제 - delete
	1. 입력/요청: `delete --id <id>`
	2. 출력/화면: 삭제 성공/실패 메시지(없는 id 처리 포함)
9. 가져오기/내보내기 - import/export
	1. 입력/요청: `import --from <csv>`, `export --out <csv> --month ...` 또는 `-from/--to`
	2. 출력/화면: 처리 건수 출력 + CSV 파일 생성/반영 확인
10. 추가 조건(최종 결과물의 필수 구성)
	1. 데이터는 3개 이상 파일로 영구 저장되어야 한다
	2. `README.md`에 실행 방법, 저장 파일 위치/형식, 주요 명령 예시, import/export CSV 스키마가 포함되어야한다.

## 과제 목표
- 파일 기반 저장(JSONL/CSV)으로 데이터를 영구 저장하고, CRUD/검색/요약/입출력을 구현
- 콘솔 프로그램을 클래스/모듈로 구조화하고, 각 계층(모델/저장소/서비스/CLI)의 책임을 설명
- `yield` 기반 제네레이터로 대용량 파일도 스트리밍 처리하는 이유와 동작 방식 설명
- 데코레이터로 공통 관심사(로그/예외/시간 측정)를 분리한 구조와 이유 설명
- 타입 힌트를 통해 입출력 계약을 명확히 했을 때 얻는 이점을 실제 코드 예로 설명

## 기능 요구 사항
### 실행 및 입력 방식
- 실행 예시는 아래를 권장
	- `python -m budget_app <command> [options]`
- 모든 명령은 `--help` 옵션으로 사용 방법이 출력되어야 함
- 입력 기본 방식은 **대화형**임
- 단, 다음 항목은 인자 방식도 **허용(권장)**
	- `search`, `list`, `summary`, `export`, `import`, `delete`
	- `update`는 **옵션 방식 또는 대화형** 중 하나를 선택해도 되나, 문서에 명확히 고정해야 함
- 옵션 표기는 리눅스 표준인 `--`로 통일해야 함

### 데이터 모델
- 거래 내역(Transaction)은 최소 아래 필드를 포함해야 함
	- `id`(유일), `type`(income/expense), `date`(YYYY-MM-DD), `amount`(양수), `category`, `memo`(선택), `tags`(선택)
	- 데이터 모델은 `dataclass` 또는 그에 준하는 구조로 정의해야 함
	- 최소 2개 이상의 클래스 사용해야 함
	- 입력 검증
		- 날짜 형식 오류, 음수/0 금액, 허용되지 않은 type, 존재하지 않는 category 등은 재입력 요구 또는 오류 메시지 출력으로 처리

### 저장 정책
- 저장 포맷은 JSONL 또는 CSV 중 1개 선택
- 저장 파일은 3개 이상(필수)로 분리해 영구 저장
- 기본 저장 폴더는 `./data`를 권장, 옵션으로 변경 가능해야 함(예: `-data-dir`)
- 초기 실행(저장 파일이 없을 때)
	- 파일이 없으면 자동 생성 또는 **초기화 안내 메시지**를 출력해야 함
	- 카테고리 파일이 빈 경우 아래 중 하나를 택해 동작을 명확히 할 것
		- 기본 카테고리 자동 생성(예: food, transport, rent, etc)
		- `category add`를 먼저 하도록 안내하고 `add`를 막음

### Add(거래 추가)
- `add` 실행 후 대화형으로 필드를 입력받아 거래를 저장해야 함
- category는 등록된 목록에 존재해야 함(없으면 안내 후 재입력/ 등록 유도)
- 저장 완료 시 생성된 `id`를 사용자에게 출력해야 함

### List(목록 조회)
- `list`는 최신순으로 거래를 출력해야 함
- `--limit N` 옵션을 지원해야 함(기본값 제공)
- 파일 전체를 한 번에 가져오지 않고, 제너레이터 기반 스트리밍 처리로 구현해야 함

### Update/Delete(수정/삭제)
- `delete --id <id>`로 특정 거래를 삭제할 수 있어야 함
- 존재하지 않는 id는 **없는 데이터**로 처리하고, 사용자 메시지를 출력해야 함
- `update`는 아래 방식 중 하나로 문서에 명확히 고정해 구현해야 함
	- 옵션 기반: `update --id <id> [--date ...][--type ...][--category ...][--amount ...][--memo ...][--tags ...]`
	- 대화형 기반: 수정할 필드만 선택/ 재입력 받는 흐름
- 파일 기반 저장에서 update/delete는 **전체 재작성/임시 파일/원자적 교체(권장)** 등 안정성을 고려해야 함

### Search(검색)
- 조건 기반 검색 지원
	- 기간: `--from`, `--to`
	- 카테고리: `--category`
	- 타입: `--type`
	- 메모 키워드: `--q`
	- 태그: `--tag`
- 검색 결과는 최신순으로 출력해야 함
- 스트리밍 처리(제네레이터 기반)을 유지해야 함

### Summary(월별 요약)
- `summary --month YYYY-MM` 입력을 받아 해당 월의 요약을 출력해야 함
- 출력 항목
	- 총 수입, 총 지출, 잔액(총 수입 - 총 지출)
	- 카테고리별 지출 합계 TOP N(`-top` 옵션 지원)
- 데이터가 없는 달은 **데이터 없음**을 명확히 출력

### Budget(예산)
- `budget set --month YYYY-MM --amount <금액>`으로 월 예산 저장해야 함
- `summary` 실행 시 예산이 설정된 경우
	- 예산 대비 사용률(%)
	- 초과 여부(초과 시 경고 문구)를 함께 표시
- 예산 데이터도 반드시 영구 저장되어야 함

### Category(카테고리)
- `category add/list/remove`를 제공해야 함
- 카테고리 삭제 시, 해당 카테고리를 사용하는 내역이 존재 시
	- 삭제를 막거나
	- 대체 카테고리를 요구해야 함

### Import/Export(가져오기/내보내기)
- `import --from \`로 거래를 일괄 등록
- `export --out \`로 조건에 맞는 거래를 CSV로 저장
- export는 `--month YYYY-MM` 또는 `--from YYYY-MM-DD --to YYYY-MM-DD` 중 하나 이상 조건을 필수로 받음
- import/export는 다음 CSV 최소 스키마를 고정

|  column  | required |        설명        |
| :------: | :------: | :--------------: |
|   Date   |    Y     |    YYYY-MM-DD    |
|   Type   |    Y     | income / expense |
| Category |    Y     |     등록된 카테고리     |
|  Amount  |    Y     |      양수 정수       |
|   Memo   |    N     |       문자열        |
|   Tags   |    N     |   쉼표(,) 구분 문자열   |
|    공통    |          |   UTF-8, 헤더 포함   |

### 기타
1. 데코레이터(Decorator)
	1. 공통 관심사(예: 예외 처리/ 로그/ 시간 측정) 데코레이터를 1개 이상 구현하고 실제 적용
2. 예외 처리 및 종료 코드
	1. 오류는 스택트레이스 대신 원인 + 해결 힌트로 출력
	2. 정상 종료는 0, 오류 종료는 0이 아닌 값으로 종료
3. 모듈화(구조화)
	1. 한 파일에 몰아넣지 않고 최소 3개 이상 모듈로 분리
	2. (권장) CLI/ 서비스/ 저장소(파일 I/O) / 모델(데이터 구조)로 책임을 나눔


## 보너스 과제(선택)
1. 백업 기능
	1. `backup` 실행 시 타임 스탬프가 포함된 백업 파일을 생성
	2. 배움 포인트: 파일 처리 + 운영 안전장치(복구 가능성)
2. 반복 내역 기능
	1. 월급/월세처럼 반복되는 내역을 등록하고, 특정 월에 자동 생성
	2. 배움 포인트: 규칙 기반 데이터 생성 + 예외 처리
3. 출력 포맷 테이블 정령
	1. 외부 라이브러리 없이 문자열 정렬로 가독성을 개선
	2. 배움 포인트: 콘솔 UX + 포맷터 분리
4. 저장 원장성 강화
	1. `update/delete` 시 임시 파일에 쓰고 `rename`으로 교체하는 방식을 적용
	2. 배움 포인트: 파일 기반 트랜잭션/원자성 사고
